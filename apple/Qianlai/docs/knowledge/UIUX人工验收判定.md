# UI/UX 人工验收判定

## 预填 / 默认值类改动的免验口径

- **场景**：分诊、开发方案或评审阶段，判断一个改动是否需要走 UI/UX 人工体验验收。
- **症状**：把「改默认预选值 / 预填来源 / 推导规则」的改动当成涉及 UI/UX，多排一轮人工验收；或反之，把真正动了界面的改动当成纯逻辑改动，漏掉人工验收。
- **原因**：UI/UX 人工验收针对的是界面结构、控件、文案、交互流程的观感与手感；默认值的推导来源变化不改变任何可见结构，其每个场景的预期输出可以被客观断言锁定。
- **做法**：判定口径 = 改动是否触碰界面结构 / 控件 / 文案 / 交互流程。仅改数据来源或推导逻辑的预填改动不涉及 UI/UX：交付方在交付评论声明「不涉及」并给出判定依据，评审方用 diff 复核声明与改动相符即可；验收面全部用「给定→当→则」的客观断言覆盖。
