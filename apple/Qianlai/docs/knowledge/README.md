# 知识库

本目录存放本项目的**普适经验**：下次还会遇到、且对本项目稳定成立的做法——判断方法、可复制的命令、操作顺序、判据、约定。它随代码一起进 git，任何人（包括 AI 助手）都能读。

## 怎么用

动手前先读下面的目录，命中主题就读对应文件，把「场景 / 做法」写进你的结论、方案或判据里。**与当前代码事实冲突时以代码为准**，并在评论里点明「知识库该条已过期」。

## 怎么写

收尾时由 Lead 沉淀，规则：

- 一个主题一个文件 `<主题>.md`；同一主题**追加**一节，不覆盖已有内容。
- 每条固定四段：

  ```
  ## <标题>

  - **场景**：什么情况下会再次遇到
  - **症状**：可观察到的表现
  - **原因**：根因（抽象描述，不引用具体行号 / commit）
  - **做法**：下次怎么做（命令 / 顺序 / 判据）
  ```

- **只写普适经验**：写完自问一句「换个任务、换个人读，这条还成立吗？」——不成立就是本次流水账，删掉。
- **不写会变的东西**：issue 号、评论 ID、文件路径、行号、commit SHA、分支名、PR 号、人名一律不写——它们会变，写进来当场过期。只写稳定的模块 / 机制名、可复制的命令、可判定的标准。
- **不写**：需求复述、代码改动摘要、任务流水账、一次性问题。
- **没有普适经验时不硬凑**：宁可不写，也不要凑一条空泛条目。
