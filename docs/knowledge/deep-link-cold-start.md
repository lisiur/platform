# 深链与冷启动竞态

## 冷启动时序（实测语义）

Widget/通知等深链到达时，App 可能刚挂载、全局数据还没 fetch 落定。此时：

- **空列表 = 「还没加载完」，不是「没有数据」**。深链处理路径遇到空数据时先执行一次 load，再重入裁决；只有**落定后**仍找不到目标才报错/降级。
- 不要在未落定时弹「选择数据源」之类的拒绝提示——冷启动用户会看到误报的错误提示。

## 目标解析的降级链

- 深链携带目标 id（绑定式链接）：目标存在且可写 → 打开并作用于**目标本身**；目标不存在（已删）→ **降级为主路径**（无参打开）；目标存在但不可写（如只读/归档）→ 明确报错。
- 「静默写进错误的目标」是最严重的失败模式：宁可拒绝也不落错。

## 作用域污染防护

- 绑定式打开只影响本次呈现的会话；**全局作用域（当前选中的账本/项目等）不被改变**。
- 普通呈现路径必须**显式清除**上次绑定残留（nil 化绑定参数），否则用户从深链进过一次后，之后手动打开的都带着上次的绑定目标。
